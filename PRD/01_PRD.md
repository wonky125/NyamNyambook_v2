## 1. 제품 개요

### 한 줄 요약
웹/SNS/유튜브에서 URL 하나로 레시피를 저장하고, 검색·태그·필터로 나만의 레시피 북을 관리하는 공개 서비스.

### 해결하는 문제
- 마음에 드는 레시피를 발견해도 북마크만 해두면 나중에 찾기 어려움
- 다양한 플랫폼(유튜브, 인스타, 블로그)의 레시피가 분산되어 있음
- 기존 Flask 앱은 JSON/정규화 테이블 혼재로 쿼리가 복잡하고 확장이 어려움

### 핵심 가치
- **URL 한 번으로 저장**: 레시피 사이트, 네이버 블로그, 유튜브 URL만 붙여넣으면 자동 파싱
- **저작권 존중**: 레시피 콘텐츠를 플랫폼 간 공유하지 않음. 원본 링크만 공유
- **나만의 레시피 북**: 요리 횟수 추적, 태그/필터로 개인화된 관리

## 2. 사용자

### 주요 사용자
- **누구**: 요리를 좋아하거나 관심 있는 불특정 다수 사용자
- **상황**: 유튜브·블로그·인스타에서 레시피를 발견했을 때 / 오늘 뭐 해먹을지 찾을 때
- **목표**: 흩어진 레시피를 한 곳에 모아 빠르게 찾고, 요리 이력을 관리하고 싶다

### 사용자 시나리오

**시나리오 1: URL 스크래핑으로 저장**
1. 유튜브에서 마음에 드는 레시피 영상 URL을 복사
2. NyamNyamBook에 접속해서 URL을 붙여넣기
3. 자동으로 제목/재료/순서가 파싱되어 저장됨

**시나리오 2: 오늘 요리할 레시피 찾기**
1. 대시보드에서 "소고기"로 검색
2. "볶음" 태그로 필터링
3. 3번 이상 해본 레시피만 보기로 좁혀서 선택

## 4. 사용자 흐름 (User Flow)

### 레시피 저장 흐름
```
랜딩 -> 소셜 로그인 -> 대시보드 -> "추가" 버튼
-> URL 입력 -> 자동 파싱 -> 결과 확인/수정 -> 저장
-> 대시보드에 새 레시피 표시
```

### 레시피 검색 흐름
```
대시보드 -> 검색창 입력 -> 태그 필터 선택
-> 요리횟수 필터 선택 -> 결과 카드 목록 -> 상세 보기
```

### 요리 이력 흐름
```
레시피 상세 -> "요리했어요" 버튼 클릭
-> cooked_count +1 -> cook_logs 기록
-> 상태 뱃지 업데이트 (0회/1회+/2회++/3회 이상+++)
```

## 5. 화면 구성 (Figma 의뢰용)

| 화면 | 설명 |
|------|------|
| 랜딩 | 서비스 소개 + 소셜 로그인 버튼 |
| 대시보드 | 레시피 카드 그리드 + 검색바 + 태그 필터 칩 + 요리횟수 필터 |
| 레시피 상세 | 이미지, 제목, 출처, 시간, 재료 목록, 조리 단계, 태그, 요리횟수 뱃지, "요리했어요" 버튼, 메모 |
| 레시피 추가 | URL 입력 탭 + 직접입력 탭, 파싱 결과 미리보기 |
| 레시피 편집 | 추가 화면과 동일한 레이아웃 |
| 프로필 | 가입 정보, 로그아웃 |

## 6. 성공 기준

- [ ] URL 하나로 10초 내에 레시피 저장 완료
- [ ] 네이버 블로그, 만개의레시피, 일반 레시피 사이트 파싱 성공률 80% 이상
- [ ] 검색어 입력 후 결과 표시까지 1초 이내
- [ ] 소셜 로그인 → 대시보드 도달까지 3클릭 이내
- [ ] Lighthouse 성능 점수 70 이상 (Flutter Web)

## 7. 안 만드는 것 (Out of Scope — Phase 1)

> 이 목록에 있는 건 Phase 1에서 만들지 않습니다.

- 레시피 커뮤니티/피드 — 이유: 저작권 이슈. 원본 링크만 공유
- YouTube/Instagram 스크래핑 — 이유: Phase 2로 분리
- 장보기 리스트 — 이유: Phase 2로 분리
- 식단 계획(밀프렙/캘린더) — 이유: 불필요하다고 결정
- 인분 자동 계산 — 이유: Phase 3로 분리
- 소셜 공유(카카오톡 공유 등) — 이유: Phase 3로 분리
- 모바일 앱(Android/iOS) — 이유: 웹 먼저, 나중에 Flutter 빌드만 바꾸면 됨
- 관리자 대시보드 — 이유: 초기 단계에서 불필요
